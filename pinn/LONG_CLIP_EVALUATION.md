## 連續推論與對齊

- 純演算法、MLP／GRU 學得電路參數的數值求解、S4、S6、S6＋PINN 均從每個錄音的第 0 樣本開始，以全部先前 Dry 更新狀態。計分起點不重設狀態，也不串接不連續片段。
- 神經網路分塊運算時保存完整遞迴狀態；每塊 8,192 樣本。S4 尾塊補齊至 128 的倍數，只丟棄補零位置的輸出。
- RiccardoVib 每個 16 樣本輸出保留其原生的前 16 樣本 Dry 歷史；不擅自改變其訓練時的模型介面。PyTorch 轉接器會再次核對已保存的 TensorFlow 參考輸出。
- 使用既有共同時間軸映射；已知一檔的 -0.75 秒素材偏移沿用 proposal.json，不以本次 Wet 或預測重新尋找對齊。
- MLP／GRU 的部署結果是學得參數後的電路求解，不是以其訓練用網路直接生成長音訊。

## 指標

七方法一律用相同區間與振幅計算 ESR、MSE、MAE、MR-STFT、RMS 包絡誤差。ESR 分母下限為 N×10⁻⁸。長片段 MR-STFT 為 FFT 512／1,024／2,048、hop=n/4、periodic Hann、center reflect、power floor=10⁻⁸；此設定不同於歷史短視窗，不直接比較兩者的 MR-STFT 數值。RMS 使用 480 樣本（10 ms）、−100 dBFS 下限，尾框按實際樣本数加權。

GPU double precision 計分已對照現有 NumPy 公式，涵蓋一般音訊、低能量、完全靜音及不足一框的尾段。逐檔等權與合併能量分別提供；不連續片段不串接後做 FFT。

## 執行與驗證

`python -m pinn.evaluate_long_clips --smoke` 已通過單檔全流程。`python -m pinn.check_long_inference` 已核對 selective recurrence 的輸出與最終狀態、原 checkpoint 的輸出，以及分塊連續性。Triton 僅加速推論，未修改 checkpoint 或訓練路徑。

正式命令是 `python -u -m pinn.evaluate_long_clips`。不重複執行正在運行的工作。每個方法／錄音的指標各自原子保存，原檔案与模型雜湊在開始及結束核對。`protocol.json` 凍結候選範圍、來源雜湊與視窗簽章，`frozen-proposal.json` 保留提案快照。

完成後會合併為 `comparison.json`，再自動建立 `output/cl1b-comparison.html`。舊短視窗 `five_models` 資料原樣保留，新長片段放在 `long_form`，不覆寫舊分數。介面檢查命令：`node pinn/comparison-ui/check_logic.cjs`；這是資料與互動邏輯檢查，不代表瀏覽器視覺驗收。
